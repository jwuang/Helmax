# 首页设计评估与需求起点

评估日期：2026-10-30。此文记录现状、已知业务和后续讨论顺序，作为逐步设计的工作底稿。候选结构和视觉方向尚待结合需求收敛。

## 已知业务

- 用户希望建设企业介绍、展示网站。
- 目标客户是制造类企业。
- 用户对主营业务的描述是：“为制造类企业提供各类电子元器件设备。”
- 已读取企业提供的 [Helmax Company Profile v2](HelmaxCompanyProfile+v2.pptx)：共 14 页，已提取全部页面文字并查看内嵌图片；本轮没有渲染 PowerPoint 的完整原始排版和动画。
- PPT 第 1 页的企业英文名为 **Helmax Technology Co., Limited**，第 1、3 页将其定位为 **Independent Distributor for Electronic Components（电子元器件独立分销商）**。这是企业自述，尚未转为网站正式发布文案。
- PPT 的核心服务为 PPV / Cost-Down（采购成本优化）、Spot Buy（现货采购）和 Stock Clearing（库存处理）；另介绍 BOM 配套、JIT 交付、VMI、质量检查与 RMA 服务。
- PPT 第 2 页介绍 Zeension、Wayland 及设备／工具图片。**用户已明确选择完整展示：官网同时覆盖电子元器件与设备／工具产品。**
- **官网统一使用 Helmax 名称及 PPT 中提供的 Helmax Logo。** 产品集中展示，分类仅通过小标题或副标题辅助识别。
- **导航中的“电子元器件”和“设备与工具”合并为“产品”。** 首页及产品页采用统一的产品展示，不按公司或业务线分别介绍和设置独立业务入口。
- **首页采用全屏分段、逐章展开的展览式体验。企业文化／理念靠前，并与首屏的文案和视觉结合。**
- **文化关键词明确为“利他、专业、效率、创新”；整体气质具有科技感；增加内容简洁的加载等待页。**
- 企业中文名称、具体访客角色、联系方式，以及各项资料对外展示的具体口径仍待补充。企业介绍与展示是当前已知的网站用途，联系合作作为后续浏览路径。

不据此推定企业自有工厂、品牌授权、库存规模、交付周期或技术服务承诺。

原评估中“按实际产品类别组织”的建议需要补充：目前 PPT 对服务模式、品牌和应用行业的说明更完整，未给出正式的元器件分类／型号目录。产品展示结构可以先确定，具体产品名称与分类在取得实际清单后补齐。

## 总体判断

现有首页具备统一的视觉骨架：浅色背景、深青色文字、少量浅绿点缀、充足留白、清晰的大标题和一致的组件语言，可以继续使用。

目前最需要调整的是业务表达和信息顺序。首页主要呈现“连接、理解、协作”的抽象理念，以及“需求梳理、方案规划、协作支持”的服务样例。制造企业访客难以由此判断供应范围、适用场景、企业实力和联系渠道。

第一轮改进应让访客能够回答：这家公司做什么、是否提供我需要的产品、有哪些可信依据、如何进一步了解或联系。

## 现状与改进优先级

| 优先级 | 实际观察 | 对访客的影响 | 建议 |
| --- | --- | --- | --- |
| 高 | 首屏标题为“以专业连接价值，让合作走得更远”，描述没有产品、行业或企业身份 | 无法迅速识别业务是否相关 | 首屏明确目标客户、核心产品和企业角色；品牌口号作为辅助表达 |
| 高 | 产品区域实际展示“需求梳理、方案规划、协作支持” | 传递的业务形象偏向通用咨询服务 | 确认实际品类后，改为主营产品入口，配真实产品图片和简明用途 |
| 高 | 首页没有可核实的产品、供货能力、项目或资质资料 | 缺少支持合作判断的依据 | 根据实际资料展示企业背景、产品品牌、应用项目、质量文件或服务能力；只选有依据的内容 |
| 高 | 联系页只显示“联系方式将在企业信息确认后公布” | 点击联系后无法完成后续动作 | 确定面向客户的邮箱、电话或其他渠道，再决定联系入口及按钮措辞 |
| 中 | 主图为通用几何建筑插画，与电子元器件／设备关联较弱 | 占据较大视觉空间，但提供的业务信息有限 | 优先考虑真实产品组合、应用现场、仓储或检测场景，依可用素材选择 |
| 中 | 手机首屏描述和卡片正文为 13px，部分说明为 8–11px | 长时间阅读和快速扫读不够轻松 | 主要正文以 16px 为起点；缩减装饰性小字，辅助说明与正文拉开层级 |
| 中 | 手机的三张服务卡片均保留较高装饰插画；390px 宽时整个服务区域约 1434px 高 | 产品信息较少，滚动篇幅较长 | 结合真实产品重排图文比例，让图片帮助识别品类，压缩重复空白和装饰 |
| 低 | 部分页脚链接点击区域高约 32–36px | 手机点击的容错空间较小 | 后续组件调整时扩大触控区域，保留合理间距 |
| 低 | 本次 Chromium 中，英文首页在 320px 宽时记录了 321px 页面宽度 | 极窄屏存在 1px 横向溢出 | 后续布局收尾时复核产生溢出的元素，并补充相应检查 |

现有样稿明确标识演示状态，未填造客户、资质或联系方式。案例、新闻没有真实内容时暂不展示，这一处理值得保留。

## 候选首页结构

当前结构：首屏口号与插画 → 企业理念 → 服务样例 → 合作方式 → 联系入口。

按当前已确认的全屏展览、文化前置、统一品牌与产品展示要求，首页采用以下章节。详见 [首页设计与原型说明](HOMEPAGE-WIREFRAME.md)。

| 模块 | 访客需要得到的答案 | 需要准备的内容 |
| --- | --- | --- |
| 首屏品牌与理念 | Helmax 以怎样的理念服务客户，提供什么？ | Helmax Logo、文化主题文案、与理念结合的主视觉、业务说明、探索理念与浏览产品入口 |
| 企业文化 | 企业重视什么，使命与愿景是什么？ | 围绕用户明确的利他、专业、效率、创新四个关键词，配合使命与愿景草案，形成独立整屏章节 |
| 企业简介 | Helmax 是怎样的企业？ | 简明企业介绍、可公开的背景和能力资料，链接至关于企业 |
| 产品展示 | 是否有我需要的产品？ | 元器件与设备／工具共用产品区域、卡片和浏览入口；分类以小标题或副标题表示 |
| 服务与能力 | 有哪些采购及合作支持？ | 经整理的采购、库存、BOM、质量与交付说明，明确适用范围；有依据时增加实力资料 |
| 联系方式 | 下一步如何沟通？ | 真实联系渠道、业务联系说明；按钮文字与到达后的内容一致 |

没有相应资料的模块先省略。产品分类、企业优势和客户名称须从真实业务中提炼。

首屏文案草案，属于依据 PPT 的编辑提炼，尚未定稿：

> 以专业，
> 成就彼此。
>
> 面向制造企业，提供电子元器件、设备与工具，以及元器件采购与供应链支持。

这只是内容结构示例，尚未形成对外宣传文案。

## 视觉方向的初步建议

- 以专业、清晰、可靠为方向，让产品和实际场景成为主要视觉素材。
- 以 Helmax Logo 的深蓝为品牌基础，用冰蓝、浅灰白与小面积青色组织不同章节；精密网格、连接节点和留白建立科技感与展览节奏。
- 首屏使用由连接路径、几何结构和利他／专业／效率／创新四个节点构成的主视觉，与文化主题文案结合；该视觉是设计意象，不表示自研芯片、实际设施或全球网点数据。
- 每章采用不同的构图：首屏品牌意象、文化章的大字与四项理念、企业介绍的图文对位、产品章的统一陈列、服务章的流程条目、联系章的简洁收尾。
- 加载等待页只包含 Helmax Logo、细进度线和“正在准备”；按真实准备状态显示，完成或超时后自动进入首页。
- 用产品名称、用途和参数建立工程领域的识别感，减少与业务无关的英文装饰语。
- 中文、繁体和英文分别检查标题换行、段落长度与导航宽度；三语可以共享设计规则，但不能只按相同字数排版。
- 章节使用正常文档滚动，桌面可提供轻量停靠和章节锚点；尊重减少动态效果设置。手机或文字较多的屏幕自然延展，避免固定高度裁切内容。

已使用 ui-ux-pro-max 的设计系统检索、Astro 实现指引和正文可读性规则。针对“corporate showcase”和“corporate”的独立产品检索未命中，未把空结果作为行业依据。补充 B2B 电子供应相关查询后，返回的通用建议强调可信资料、业务概览和清晰联系路径；这些原则与本项目相符。自动返回的具体字体、蓝色配色、报价表单和轮播不直接纳入方案，需由真实品牌、内容与目标决定。当前没有写入正式的设计系统文件。

## 逐步推进方式

| 步骤 | 讨论重点 | 形成的可检查成果 |
| --- | --- | --- |
| 1. 明确业务与目标 | 产品范围、企业角色、主要访客、希望访客完成的动作 | 一页业务与网站需求简报 |
| 2. 整理内容与素材 | 企业介绍、产品分类、图片、实力依据、联系方式、语言需求 | 内容清单、素材清单、导航与页面结构 |
| 3. 设计首页线框 | 首屏表达、模块顺序、信息取舍、手机阅读路径 | 桌面和手机首页低保真线框 |
| 4. 确定视觉方案 | 结合品牌和真实素材比较设计方向，确定字体、颜色、间距与组件 | 首页视觉稿及设计规则 |
| 5. 实现与验收 | 在现有 Astro 项目中实现，处理三语与响应式布局 | 可运行页面、视觉截图和适当的检查结果 |

已确认企业介绍／展示用途、Helmax 统一品牌、统一产品展示、全屏分段体验，以及文化前置并结合首屏的要求。现阶段提供可滚动的本地视觉概念稿，用来讨论各屏构图、阅读节奏与文化表达。正式产品清单、具体文案、联系方式与待核对的数据在内容整理阶段补充。

## 原官网评估的检查范围与证据

- 阅读了首页模板、三语文案、企业配置、组件、样式和现有浏览器测试。
- 启动当前源码的本地 Astro 开发预览，用已安装的 Chromium 149.0.7827.55 检查。

- 本次没有修改网站页面或业务内容，也没有运行完整 `pnpm verify`。开发预览不用于推断正式环境性能，Firefox、WebKit 与真实移动设备尚未在本轮检查。
